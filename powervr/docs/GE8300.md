# GE8300 / Minecraft 1.20.1: experimental performance investigation

User report: r1 imports successfully in original Zalith, but produces an unstable
~25 FPS in Minecraft 1.20.1. Device model, CPU, driver, settings, mods, logs and
frame-time measurements have not yet been supplied. This is not a controlled
benchmark and does not establish whether the bottleneck is GPU, CPU, or JVM.

## What r2 changes

Removes repeated extension enumeration and function lookup from our indirect
multidraw port. No features are disabled, no errors suppressed, no version string
spoofed, and no draw calls skipped. Does not force batching or tile-renderer
workarounds across all PowerVR generations. This improvement is useful only when
this entry point is actually used. It is not a general GE8300 optimization claim.

## Reproducible A/B test

1. Preserve the old import ZIP and a copy of the game instance/options.
2. Use the exact same Minecraft 1.20.1 instance, Java, mods, resolution, world,
   camera route, render distance and device power settings for r1 and r2.
3. Warm up in the same area, then compare standing still and moving into new
   chunks separately. Alternate r1/r2 order to reduce thermal/order bias.
4. Record frame-time samples if your existing overlay/profiler provides them.
   Compare median and slow-tail frame times, not just the highest FPS number.
5. Repeat at least 3 times. Do not compare a cold shader cache against a warm one.
6. Send the phone/SoC model, Android version, GL renderer/version strings,
   render/simulation distance, resolution, mod list, and launcher log.

## Low-load diagnostic settings (not an automatic renderer change)

Try render distance 4 chunks, simulation distance 5 chunks, Fast graphics,
clouds off, minimal particles, entity shadows off, no shader packs, and 50%
launcher resolution scale. Back up settings first. These trade image quality
and draw distance for load reduction and are not guaranteed to improve FPS.

Compare 100% vs 50% resolution while stationary: a large improvement suggests
pixel/shader load is important; little change suggests investigating CPU/driver
submission, chunk work or JVM pauses next. This is a diagnostic clue, not proof.
Compare stationary vs loading new chunks to isolate chunk generation/upload spikes.
A 30 FPS cap can reduce visible pacing variation if sustained, but is not a speedup.

Do not install random Vulkan drivers or overclock/disable thermal protection.
A stable experience on every PowerVR model cannot be promised from one device.
